AgentRouter 公益 API 中转站：注册、国内镜像与 Codex 排错

Mutec2026-11-062026-11-06

本文作者：奈奈

前言

AgentRouter 是一个公益性质的大模型 API 中转站，控制台和接口体系基于 New API / One API 一类架构，支持 OpenAI、Anthropic 等兼容协议。我主要拿它做个人编程、临时调试和学习测试，不把它当生产接口。

站内模型会随上游资源动态调整，目前常见的有 gpt-6-astra、Sol 系列等。具体模型名、倍率和可用状态，始终以控制台的模型列表与公告为准。

这是第三方公益中转服务，不提供稳定性承诺。不要上传隐私、密钥、商业源码等敏感数据，也不建议接入生产环境。

使用时要注意什么

  1. 公益站在高峰期可能限流或耗尽公共额度。遇到 402 Budget pool quota has been exhausted 时，等待下一批额度、重试请求，或者临时切换其他模型。
  2. 模型上下线很快，配置前先去控制台确认模型 ID。名称写错或模型已下线时，通常会直接报 503。
  3. 日常代码编写、内容生成和学习测试基本够用，但稳定性看上游，不要把它当作唯一接口。
  4. gpt-6-astra 烧额度很快，而且供应策略会调整，长任务之前最好先看公告。

gpt-6-astra 适合关键任务，不适合无节制地跑长上下文。公益额度看起来很多，真正烧起来也很快。

编排工具与 probation 分组

AgentRouter 会识别客户端和使用场景。非编程用途、异常调用方式或未受支持的客户端，可能被放进 probation 分组，调用倍率会翻倍。官方说这个分组会动态更新，恢复一段时间的正常使用后可能移出。

建议优先使用官方列出的常见工具，例如 Claude Code、Codex、OpenCode、Cline、Roo Code、Hermes 等，并按对应文档配置，不要拿普通聊天软件硬接。

最后

AgentRouter 的优点很直接：免费、注册方便、支持的编程工具多，还有国内备用镜像。缺点也同样明显：公共额度会波动，模型可能临时上下线，probation 的判定也不够透明。

我的定位是把它当个人开发和学习时的备用接口。能用就用，关键项目和敏感内容还是走官方 API 或稳定的付费服务。
